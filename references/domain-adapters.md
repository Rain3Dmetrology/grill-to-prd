# grill-to-PRD 领域适配器（Domain Adapters）

**机制**：grill-to-PRD 主体领域无关；领域差异通过本文件定义的适配器注入。
每个适配器回答三个问题：① 事实从哪里取证；② 哪些来源适合该领域；③ 引导时优先关注哪些领域维度。

**重要边界**：本文件中的来源列表仅描述事实来源适用性与可信度，不是网络出口 allowlist、供应商批准、安全认证或工具权限。网络访问、凭据、工具调用和外部写入由运行时与组织策略控制。

---

## 内置适配器

### 1. 代码库（codebase）

| 项 | 定义 |
|---|---|
| **事实源** | git 仓库（grep/read/log）、构建产物、CI 配置、**deepwiki MCP（快速仓库结构/文档全景：read_wiki_structure/ask_question）** |
| **来源适用性** | GitHub 仓库内容、项目官方文档、依赖官方文档；重要事实回读原始文件 |
| **领域维度** | 命名空间/API 形态、C++/语言标准、依赖版本、导出宏、仓库边界、跨仓库一致性、测试挂载点（seams） |

**规则**：代码库主张应记录仓库、分支/提交、文件路径或命令来源；判断决策是否已经发生时检查 git log。deepwiki 适合作为快速索引，但关键结论必须回读原始代码、配置或测试结果。测试 seam 优先复用已有验证入口，不设固定数量。

### 2. HF 模型（huggingface）

| 项 | 定义 |
|---|---|
| **事实源** | HF MCP（model_search / hub_repo_details 含 model card / dataset_search / paper_search / hf_doc_search） |
| **来源适用性** | Hugging Face 官方模型卡、论文原文、官方 benchmark leaderboard |
| **领域维度** | 模型存在性、参数规模、license、benchmark、设备参数预算（fp16≈GB÷2, Q4≈GB×2）、量化方案 |

**规则**：绝不假设模型存在；模型存在性、license、参数和 benchmark 均需记录来源与获取时间；选型决策输出比较表与推荐理由。

### 3. 市场调研（market）

| 项 | 定义 |
|---|---|
| **事实源** | 行业报告、官方统计、上市公司披露、多源交叉验证 |
| **来源适用性** | 官方统计、监管/交易所披露、可追溯行业报告；按具体子领域选择来源 |
| **领域维度** | 市场规模（TAM/SAM/SOM）、竞品格局、趋势、定价、增长驱动 |

### 4. 专利/知识产权（patent）

| 项 | 定义 |
|---|---|
| **事实源** | 专业检索（patsnap 等，若已连）、专利局官方数据库 |
| **来源适用性** | 专利局官方数据库与可核对的法律状态来源 |
| **领域维度** | 专利族、引用、法律状态、权利要求边界 |

### 5. 商业模式（business-model）（v0.3.0 新增）

| 项 | 定义 |
|---|---|
| **事实源** | 行业报告、竞品公开信息（官网/财报/发布会）、上市公司披露、多源交叉验证 |
| **来源适用性** | 公司官网、财报、交易所披露和行业报告；标注发布日期 |
| **领域维度** | 价值主张、目标客户细分、收入模式、成本结构、渠道、竞争壁垒、定价、市场时机 |
| **追问词典** | 谁付钱/付多少/为什么选你不选竞品/扩张路径/盈亏平衡点/护城河 |

**规则**：关键商业判断优先依据官方披露/一手财报；竞品判断须标注来源与时间；市场规模用 TAM/SAM/SOM 分层。

### 6. 日常生活（daily-life）（v0.3.0 新增）

| 项 | 定义 |
|---|---|
| **事实源** | 生活常识、受信任生活服务源（官方渠道）、本地信息、多源交叉验证 |
| **来源适用性** | 政府、公共事业、服务商官方渠道及可交叉验证的本地信息 |
| **领域维度** | 预算、地点、时间窗口、参与方偏好、风险偏好、优先级（MoSCoW 轻量）、验收标准（可验证） |
| **追问词典** | 目标/范围/预算/时间/相关方/限制条件/怎么算成功/冲突时保哪个 |

**规则**：生活场景使用轻量需求记录；避免过度追问；决策留痕仅对不可逆或高影响选择（如大额支出、长期承诺）。

## 百科型事实源模式（v0.3.0）

任何领域可为关键对象建立"结构百科 + 问答"事实源（如 deepwiki 之于代码仓库）：
- 市场领域 = 行业百科 / 竞品百科
- 生活领域 = 本地生活知识库 / 服务百科
- 适配器可声明百科源（`百科源: <名称/接入方式>`），加速线索定位与背景梳理
- **红线**：关键或不可逆决策仍须回读一手来源确认（AI 生成文档可能过时或有偏差）

## 自定义适配器（模板）

```markdown
### N. <领域名>

| 项 | 定义 |
|---|---|
| **事实源** | <适用于该领域的文件/API/官方文档/数据源> |
| **来源适用性** | <该领域适合使用的原始来源；不代表权限许可> |
| **领域维度** | <引导时优先追问的领域特有维度> |

**规则**：<该领域的取证/引导特殊规则>
```

**挂载方式**：根据任务内容选择并声明适配器；只有领域或来源选择存在实质歧义时才询问用户。适配器不授予网络、工具或数据访问权限。
**扩展方式**：新增适配器 = 在本文件追加一节（follow 模板），随 skill 独立仓库迭代维护。
