# grill-to-PRD 领域适配器（Domain Adapters）

**机制**：grill-to-PRD 主体领域无关；领域差异通过本文件定义的适配器注入。
每个适配器回答三个问题：① 事实从哪取证（E1）；② 受信任域名白名单；③ 引导时优先追问的领域特有维度。

---

## 内置适配器

### 1. 代码库（codebase）

| 项 | 定义 |
|---|---|
| **事实源** | git 仓库（grep/read/log）、构建产物、CI 配置、**deepwiki MCP（快速仓库结构/文档全景：read_wiki_structure/ask_question）** |
| **白名单** | github.com + 项目官方文档 + 依赖官方文档 |
| **领域维度** | 命名空间/API 形态、C++/语言标准、依赖版本、导出宏、仓库边界、跨仓库一致性、测试挂载点（seams） |

**规则**：代码库事实强制 E1（真读到）；"决策已发生"识别须查 git log 提交历史（区分历史决策 vs 待做决策）。
**取证分层**：deepwiki 提供**快速索引 E1**（仓库架构/模块关系全景，比 grep 高效），但**不可逆抉择级结论仍须回读一手代码确认**（deepwiki 是 AI 生成的二手文档，可能过时/有偏差——对齐 R13"凭据三级判定"）。**seams（测试缝隙）取证**：优先复用已有 seam，理想数量=1，seam = G 门验收命令挂载点。

### 2. HF 模型（huggingface）

| 项 | 定义 |
|---|---|
| **事实源** | HF MCP（model_search / hub_repo_details 含 model card / dataset_search / paper_search / hf_doc_search） |
| **白名单** | huggingface.co / arxiv.org / 官方论文 / 模型卡原文 / 官方 benchmark leaderboard |
| **领域维度** | 模型存在性、参数规模、license、benchmark、设备参数预算（fp16≈GB÷2, Q4≈GB×2）、量化方案 |

**规则**：绝不假设模型存在；选型决策输出比较表 + ⭐ 推荐。

### 3. 市场调研（market）

| 项 | 定义 |
|---|---|
| **事实源** | 行业报告、官方统计、上市公司披露、多源交叉验证 |
| **白名单** | 行业权威域名（依领域配置） |
| **领域维度** | 市场规模（TAM/SAM/SOM）、竞品格局、趋势、定价、增长驱动 |

### 4. 专利/知识产权（patent）

| 项 | 定义 |
|---|---|
| **事实源** | 专业检索（patsnap 等，若已连）、专利局官方数据库 |
| **白名单** | 专利局官方域名 |
| **领域维度** | 专利族、引用、法律状态、权利要求边界 |

### 5. 商业模式（business-model）（v0.3.0 新增）

| 项 | 定义 |
|---|---|
| **事实源** | 行业报告、竞品公开信息（官网/财报/发布会）、上市公司披露、多源交叉验证 |
| **白名单** | 行业权威域名、交易所披露系统、公司官网 |
| **领域维度** | 价值主张、目标客户细分、收入模式、成本结构、渠道、竞争壁垒、定价、市场时机 |
| **追问词典** | 谁付钱/付多少/为什么选你不选竞品/扩张路径/盈亏平衡点/护城河 |

**规则**：商业模式事实强制 E1（官方披露/一手财报）；竞品判断须标注来源与时间；市场规模用 TAM/SAM/SOM 分层。

### 6. 日常生活（daily-life）（v0.3.0 新增）

| 项 | 定义 |
|---|---|
| **事实源** | 生活常识、受信任生活服务源（官方渠道）、本地信息、多源交叉验证 |
| **白名单** | 生活服务权威域名（依场景配置） |
| **领域维度** | 预算、地点、时间窗口、参与方偏好、风险偏好、优先级（MoSCoW 轻量）、验收标准（可验证） |
| **追问词典** | 目标/范围/预算/时间/相关方/限制条件/怎么算成功/冲突时保哪个 |

**规则**：生活场景用轻量治理（只强制 B1 冻结 + 验收可验证 + MoSCoW 轻量优先级）；避免过度追问（frontier 空即停）；决策留痕仅对不可逆抉择（如大额支出、长期承诺）。

## 百科型事实源模式（v0.3.0）

任何领域可为关键对象建立"结构百科 + 问答"事实源（如 deepwiki 之于代码仓库）：
- 市场领域 = 行业百科 / 竞品百科
- 生活领域 = 本地生活知识库 / 服务百科
- 适配器可声明百科源（`百科源: <名称/接入方式>`），加速 E1 取证
- **红线**：不可逆抉择级结论仍须回读一手来源确认（AI 生成文档可能过时/有偏差——对齐 R13"凭据三级判定"）

## 自定义适配器（模板）

```markdown
### N. <领域名>

| 项 | 定义 |
|---|---|
| **事实源** | <agent 取证 E1 的渠道> |
| **白名单** | <受信任域名，白名单外结论最高 INFERRED> |
| **领域维度** | <引导时优先追问的领域特有维度> |

**规则**：<该领域的取证/引导特殊规则>
```

**挂载方式**：用户显式声明"本需求属 X 领域"→ 本 skill 加载对应适配器；未挂载 → 通用取证（多源交叉 + E1 一手来源）。
**扩展方式**：新增适配器 = 在本文件追加一节（follow 模板），随 skill 独立仓库迭代维护。
